# Google 账户冷启动恢复调查

调查时间：2026-10-04 至 2026-10-05。当前状态：已通过实体 iPhone 的历史记录确认登录中转入口导致账户编号无法保存，构建 13 已修复并通过回归测试。真实 Google 登录后杀进程重开的最终页面仍需验收；下文保留修复前证据与验证边界。

## 2026-10-05 实体 iPhone 证据与构建 13 修复

实体 iPhone 当前可由 `devicectl` 读取 App 自身数据，安装构建为 11。只读检查偏好确认：唯一活跃记录的入口为 `https://accounts.google.com/AccountChooser`，`continue` 指向官方 Antigravity 的 `/r/` 实例页面；记录有账户标签，但记录中的 `googleSessionIndex` 和全局 `Antigravity_Last_Google_Session_Index` 都为空。输出仅使用路径类别和布尔状态，不记录实际实例 ID、邮箱或完整链接。

这解释了为什么构建 11 的普通远程 URL 测试通过、手机仍失败：`recordAccountRoute` 校验的是历史记录的原始 URL，要求它必须属于官方远程页面。历史记录为 AccountChooser 时，所有最终页面的账户编号都被这个 guard 拒绝；`prepareConnection` 也原样重新打开中转入口，无法应用账户路径。

构建 13 增加：

1. 对已知 Google 登录域的 `continue` 最多解包 5 层，且只接受最终官方远程页面。不会把任意站点的 redirect 参数当作连接目标。
2. 旧 AccountChooser 历史记录在读取时迁移到真实远程实例链接，保留记录 ID、备注及账户标签；入口归一化同样解包，覆盖扫码、粘贴、历史和手动连接。
3. 所有首次 WebKit 请求再次归一化，账户选择持久化时也兼容旧中转记录。
4. 增加与手机记录结构相同的迁移、会话参数保留、被动回退、重开恢复测试，以及恶意/无效 continuation 拒绝测试。

完整的“Google 网页登录 → 账户切换 → 杀进程 → 重开后最终头像”真机 UI 验收仍未完成：Xcode 设备交互服务当前仅列出模拟器，拒绝选择该实体 iPhone；CLI 可读取偏好并不代表已能完成 UI 自动化。这里不以偏好数据替代最终网页验收。

## 2026-10-05 修复进展（构建 12）

已修复两个可证实的客户端问题：主页面监听遗漏 `ogs.google.com` 账户菜单 iframe，以及被动页面提交覆盖用户选择。

1. `GoogleAccountBridge` 注入所有 frame，仅接受官方远程页面与账户菜单来源。点击菜单账户链接时，读取数字 `authuser` 或菜单账户路径，直接交给原生层处理。
2. 原生层立即保存主动选择，再以 `/u/N/` 加载原来的实例和会话，避免账户菜单弹窗跳到实例列表后才记录账户。
3. `recordAccountRoute` 仅补齐尚无偏好的记录。已有偏好只能被主动选择或明确输入的账户链接更新。
4. 第一次请求带上持久化编号；已提交页面偏离选择时最多重试一次，不生成跳转循环；重试仍失败也保留偏好。
5. 账户菜单关闭提示的状态跨网页导航保留；新的连接重置该状态。取消旧导航的错误不再显示为连接失败。
6. 普通实例链接保留正常导航，不能当作账户菜单选择而误跳回原实例。

构建 12 的验证范围：JavaScript 菜单 iframe 事件捕获、默认账户主动选择、普通链接不拦截；原生立即持久化、被动默认回退不覆盖、恢复尝试有界、实例与会话保留；独立进程验证持久化后的首次请求。真实登录 Google 的实体 iPhone 冷启动仍需验收。

以下为修复前调查记录，其“尚未修复”“未上传”表述只描述 2026-10-04 的状态。最终上传结果另记录在 TestFlight 发布记录中。

## 1. 已确认的结论

Google Antigravity 网页支持非默认账户。选择账户依赖当前浏览器会话和账户路由；“Cookie 仍有效”不等于“无账户参数的入口会记住上次选中的账户”。

在已登录多个账户的真实 Safari 中完成以下对照（账户以 A/B 匿名标记）：

| 操作 | 最终地址 | 结果 |
| --- | --- | --- |
| 打开根地址 | `https://antigravity.google.com/` | 默认账户 A，无实例 |
| 点击头像，再选第二个已登录账户 | `/u/1/?pageId=none` | 账户 B，出现其离线实例 |
| 直接重新加载账户地址 | `/u/1/` | 仍为账户 B |
| 再打开无账户编号的根地址 | `/` | 回到账户 A |

这证明同一登录会话内，无账户编号入口会落回默认账户；也排除了“Google 网页只能用默认账户”。此实验不是 iPhone WKWebView 杀进程实验。

## 2. Google 实际机制

检查当日官方网页交付的 JavaScript，`ConfigService.init` 默认 `sessionIndex` 为 `0`，优先解析路径中的 `/u/(数字)`。OAuth 回调有额外的 `state` 和 `sessionStorage` 恢复分支。普通根入口不会因为此前在另一页面使用过账户 1 就自动变成账户 1。

真实 Google 账户菜单为第二账户生成 `?authuser=1&pageId=none`，以新窗口方式打开，最终由服务器规范化到 `/u/1/`。应用把新窗口请求转为当前 WKWebView 导航；需要真机记录确认菜单请求是否经过了完整跳转。

不带任何登录 Cookie 的独立 HTTP 请求也显示：

| 请求 | 响应 |
| --- | --- |
| `/u/1/` | 302 到 `/` |
| `/?authuser=1` | 302 到 `/` |
| `/u/1/r/test-instance` | 302 到 `/r/test-instance` |

这只证明：在该无登录环境下，服务器会移除账户路由。不能据此认定用户手机的 Cookie 丢失。

官方资料：

1. [Google 多账户说明](https://support.google.com/accounts/answer/1721977?hl=zh-Hans)：无法确定使用哪个账户时可能应用默认账户。
2. [Antigravity Remote Control](https://antigravity.google/docs/remote-control)：浏览器和电脑需使用相同 Google 账户；远程链接本身不保证同步当前电脑的账户选择。
3. [Apple WKWebView websiteDataStore](https://developer.apple.com/documentation/webkit/wkwebviewconfiguration/websitedatastore)：默认数据存储持久化，不代表与 Safari 共用会话。

## 3. 客户端已确认的缺口

### 3.1 页面结果与用户选择混为一谈

位置：`AppSettings.recordAccountRoute`。

所有已提交的数字账户路径都会写入偏好。已保存 2 → 提交 `/u/0/r/mac` → 下次恢复 0，已用原生测试复现。没有区分主动选择账户 0 与被动跳转到账户 0。

注意：无编号根路径不会直接覆盖已保存的编号；只有可解析的数字账户路径才进入此写入分支。因此不能把所有默认账户回退都归因于这一处代码。

### 3.2 以前缺少真实跳转证据

没有保存首次请求、服务端 redirect、弹窗请求、已提交路由的脱敏记录。只看到最终默认账户，无法区分：未保存选择、恢复时未带编号、服务器丢弃编号、账户会话编号变化。

### 3.3 之前的验证范围不足

UserDefaults 跨进程测试证明保存值能还原；WebKit 测试使用本地 HTML 和 `history.replaceState`，证明观察器能捕获路径变化。两者都没有验证已登录 Google 的 HTTP 重定向、Cookie 可用性或手机实际启动入口。

之前据这些结果断言问题已解决，证据不足。

### 3.4 版本与实际启动入口尚未对齐

App Store Connect 查询显示：1.0.0 (11) 已处理完成且可内部测试，但外部状态为 `READY_FOR_BETA_SUBMISSION`，未完成外部测试发布。上传成功不等于公开 TestFlight 链接的测试者已收到新包。尚未获得用户实际安装的 TestFlight 构建号，不能断言用户一定在旧包。

当前源码 `MainContainerView` 初始状态为连接大厅，没有冷启动自动进入网页逻辑；用户描述是“打开 App 后自动进入网页”。需要核对实际构建、启动入口，以及是否为网页安装到桌面的入口；不能把这些可能性当成事实。

设置页原先写死 `1.0.0 (Build 1)`，且错误声称 Google 登录交给 Safari 并共用登录状态；实际实现是 App 内 `.default()` WKWebView。两处信息均已修正。

### 3.5 手机选择与电脑选择是不同状态

恢复手机上次选定账户可以由应用实现。电脑切换 Google 账户不会自动更新手机独立的网页会话。当前应用也没有取得“电脑现在选中了哪个 Google 账户”的可靠信号，不能从一个无账户身份的实例链接凭空推断。

## 4. 本次实施

1. 保留上一轮头像点击后关闭账户提示的改动；不把提示消失当成账户恢复成功。
2. 增加本机最近 120 条脱敏诊断：进程标记、实际版本、恢复编号、准备入口、首次请求、导航动作、弹窗、服务端跳转、提交页面、路由观察和保存、头像识别、错误码。

实体 iPhone 当前不可连接，未完成登录 Google 后杀进程重开的真机验证。还需安装本次诊断版本，选择非默认账户后完全关闭并重开，再取得本机诊断：

| 证据 | 判断方向 |
| --- | --- |
| 切换后从未出现 `routeSaved` 非零编号 | 选择捕获 / 弹窗跳转链不完整 |
| 保存非零编号，但新进程 `prepareTarget` 或 `loadRequested` 无编号 | 恢复入口或匹配记录问题 |

| 首次请求与提交均为非零编号，但显示错误账户 | 数字编号对应的会话身份变化，需另行核实身份映射 |

必要的最终验收：真实 Google 多账户、非默认账户选择、杀进程、重开、直接连接与历史连接、主动切回默认账户；每项检查最终头像和远程实例归属，不能只检查 URL。
